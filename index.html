A / 01

OfferOS

将简历与岗位要求，整理成可解释的求职行动建议。

面向：需要判断投递优先级的求职者

体验产品 ↗阅读案例查看 GitHub

已实现应用 · 本轮仅验证规则／模拟模式

项目思考与资料

目标用户与范围

需要判断投递优先级的求职者

核心问题

匹配分数缺少证据，报告与实际准备脱节。

核心价值／研究结论

围绕画像、岗位解析、匹配与行动建议设计连续决策链路。

主要流程

简历／JD → 解析 → 四维匹配 → 行动报告／历史

最终产出／已有资料

岗位分析与准备建议；本轮为规则／模拟结果

产品判断与取舍

当前源码采用知识技能、经验、能力、个性四维评分，硬门槛独立警示；旧主页三维权重已不再适用。

当前局限与下一步

公开入口是虚构人物演示。真实 LLM、截图解析和外部背调依赖服务；本轮不以模拟结果认定真实 AI 能力已验收。

在线体验：http://47.237.109.221/

A / 02

PaperMind

把专业 PDF 转为可回查来源的交互讲解，在阅读中补充知识。

面向：硕博研究生与科研助理

体验产品 ↗阅读案例查看 GitHub

专业 PDF 阅读工作台 · 已有应用实现

项目思考与资料

目标用户与范围

硕博研究生与科研助理

核心问题

文献信息混淆，综述易退化成摘要堆砌。

核心价值／研究结论

连接整篇讲解、原文引用、图表提问与个人概念库，让理解过程可以继续深入和回看。

主要流程

导入 PDF → 生成交互讲解 → 回查原文／继续提问 → 保存概念／补充页面

最终产出／已有资料

交互阅读页面、来源引用、连续对话与个人概念库

产品判断与取舍

以完整主线和来源回查支撑理解；页面补充与概念保存由用户分别确认，不用测验分数代替理解。

当前局限与下一步

当前为共享单用户工作台，尚无账号或多人隔离；新生成、OCR 和 Copilot 依赖千问与模型权限，可能产生费用。体验地址来自现有 README，本轮未复验在线服务。

在线体验：https://papermind.47.237.109.221.sslip.io/

宝宝成长相册

将散落的成长照片，组织成家人共写的私密时间轴。

面向：需要共同记录宝宝成长的家庭

体验产品 ↗阅读案例查看 GitHub

已实现全栈代码 · 服务依赖未验收

项目思考与资料

目标用户与范围

需要共同记录宝宝成长的家庭

核心问题

照片散落在聊天中，记录和访问权限缺乏统一管理。

核心价值／研究结论

以记录和家庭角色为核心，设计上传、时间轴和邀请流程。

主要流程

建立家庭 → 上传照片和记录 → 时间轴查看 → 家庭协作

最终产出／已有资料

成长记录与相册；真实上传依赖数据库和对象存储

产品判断与取舍

家庭协作与单人本地预览是不同能力；不把示例家庭或本地回退视为已验证的权限隔离。

当前局限与下一步

完整闭环依赖 PostgreSQL 和私有 OSS；本轮不连接远程数据库或云存储。本地示例可浏览。

在线体验：https://album.47.237.109.221.sslip.io/

实际项目资料

  • 项目说明与配置
  • PRD（PDF）打开 PDF

桌面便签板

把瞬间想到的事，留在每天都会看见的桌面上。

面向：Windows 桌面轻量记录用户

下载应用 ↗阅读案例查看 GitHub

Windows 应用已实现 · 原生流程待验收

项目思考与资料

目标用户与范围

Windows 桌面轻量记录用户

核心问题

打开大型笔记工具会打断当前工作。

核心价值／研究结论

悬浮入口、便签编辑与本地文件持久化。

主要流程

当前局限与下一步

不是网页应用；本轮环境无法完整操作原生窗口验证。查看详情中的本地启动说明，不提供伪造网页体验入口。

本地启动（工作目录：产品经理）：cd '桌面便签板/app'; npm start

B / 01

自媒体 AI 工作台

让灵感经过制作、排期与复盘，成为可以持续推进的内容。

面向：独立内容创作者

本地可用 · 创作管理闭环

目标用户与范围

独立内容创作者

核心问题

素材、稿件与发布计划分散，下一步行动容易丢失。

核心价值／研究结论

把灵感转成项目，以任务和稿件承接创作，再用手动数据快照复盘。

主要流程

记录灵感 → 转为项目 → 编辑稿件与任务 → 安排发布 → 录入数据／导出

最终产出／已有资料

可编辑的项目、稿件、排期和 JSON／Markdown 导出文件

产品判断与取舍

优先打通人工创作管理，AI 只辅助；来源与稿件分开管理，避免没有出处的内容进入成稿。

当前局限与下一步

本地存储是真实功能；预置内容是示例。AI 未配置时为 Mock，不会自动发布到社交平台；云端同步需 Supabase。

实际项目资料

  • README 与能力边界
  • 原始 PRD（Word）打开

AI 采访教练

练习采访中的提问、追问和复盘，而非求职面试。

面向：采访初学者与内容创作者

可运行流程 · AI 模板演示

目标用户与范围

采访初学者与内容创作者

核心问题

缺少低成本反复练习提问与追问的环境。

核心价值／研究结论

通过采访提纲、模拟嘉宾对话与训练复盘衔接下一次练习。

当前局限与下一步

GLM 等模型调用未在本轮验证；模板分数不能代表真实采访能力，历史仅在当前浏览器。

B / 03

知音 · 智能定调

为已经选好的歌曲，建议更适合用户舒适音域的调。

面向：K 歌用户

黑客松概念原型

目标用户与范围

K 歌用户

核心问题

歌曲原调与自己的舒适音域不匹配。

核心价值／研究结论

结合舒适音域与歌曲音高时长分布，探索半音建议。

主要流程

测音域 → 选歌 → 建议升降调 → 原型体验

最终产出／已有资料

交互原型、定调算法与竞品研究

产品判断与取舍

把测音域作为定调前置步骤，聚焦“这首歌怎么唱”，而非泛化声音测评。

当前局限与下一步

歌曲数据与宿主应用为概念原型，不能标为接入全民 K 歌的正式产品。两个目录为版本副本，合并展示。

实际项目资料

  • 当前实现与边界

  • 选题与 PRD 评估
  • MeChoir PRD

当前局限与下一步
